Once you are running more than a handful of sessions, the list becomes the
problem. Happier gives you four ways to impose order on it, and all four are
stored on the server, so the arrangement you build on your laptop is the one you
see on your phone.

Folders are on by default. Nothing here needs turning on unless your server
operator has disabled `sessions.folders`.

## Folder explorer

By default the sidebar is a folder explorer, like the one in VS Code: each
machine's folders, starting from `~` (your home folder), with every session
inside the folder it was started in. Sessions started outside your home folder
appear under `/`; when sessions come from several machines, each machine gets
its own top row.

- Press a folder to open or close it. Folders open by default when sessions
  sit below them; other folders start closed, and open folders also list the
  machine's other subfolders so you can start a session anywhere.
- Folders sort by name. A folder shows how many sessions sit below it, and a
  green dot when one of them is running. Sessions that are not running are
  dimmed.
- Press **+** on a folder to start a session in that folder with the agent
  picked above the list. With a mouse, **+** shows when you hover, focus or
  open the folder; on touch screens it is always there.
- The **⋯** menu next to search refreshes the folder listings, closes every
  open folder, shows hidden folders (names starting with a dot), and hides or
  shows stopped sessions.
- **Open folder…** in the same menu works like Open Folder in VS Code: pick a
  folder on the machine and the tree starts there, for example at `~/code`.
  Sessions started elsewhere stay one click away under **Other locations**.
  **Back to home folder** returns the tree to `~`. The opened folder is saved
  with your account, so your other devices open it too.
- Right-click a folder (long-press on a phone), or use its own **⋯** button,
  for the folder's menu, like the Explorer in VS Code:
  - **New session in folder** starts a session there with the agent you pick
    (Claude Code, Codex, …).
  - **Create folder** asks for a name; a path such as `notes/2026` makes the
    folders in between too.
  - **Copy path**, **Open as top folder** (the tree then starts there, as with
    **Open folder…**) and **Refresh**.
  - **Rename** keeps the folder where it is. It is refused while sessions
    started in the folder, because they would lose their folder.
  - **Delete folder** deletes the folder with everything in it after you
    confirm, and cannot be undone. It waits until no session runs inside.

  Rename and delete are not offered for the top folders (`~`, `/` or an opened
  folder), the home folder or a folder that holds it.
- Right-click a session for the same menu as its **⋯** button.
- The **Sessions | Files** switch above the explorer picks its view. **Sessions**
  shows the folders with your sessions, as described above. **Files** turns the
  explorer into a file manager for the machine: folders and their files, no
  sessions. Selecting a file opens a read-only preview (text with syntax
  highlighting, or the picture); files above the machine's read limit (2.5 MB
  by default) and binary files say so instead. A file's right-click menu copies
  its path, downloads it (the share sheet on a phone), renames or deletes it.
  The choice is remembered on each device.
- Search and tag filters show only the folders above each match.

To delete a session, use **Delete session** at the bottom of its **⋯** menu and
confirm. Deleting cannot be undone. A running session has to be stopped first:
**Stop session** is in the same menu, and **Delete session** appears once it has
stopped.

Listing folders needs the machine to be online. When it is offline, the
explorer still shows the folders that hold sessions.

To use grouped lists instead, change **Settings → Sessions → Sidebar layout**
to List; **Active sessions grouping** then picks Project or Date. The folders
described below appear in the list layout.

## Agent picker

The select box above the list picks one agent (CLI) — Codex, Claude Code and
so on — and the list shows that agent's sessions. It offers the agents
installed on your online machines and any agent that already has sessions, with
the number of sessions beside each. Until you pick one, it follows the agent of
your most recently updated session. The pick is remembered on that device, and
**+** on a folder starts a session with that agent.

## Folders

Folders group sessions the way directories group files, and they nest.

- Create, rename, move and delete them, and nest one inside another.
- Assign a session by dragging it onto a folder, or through the session's
  context menu.
- Drag a session onto the workspace root to take it out of a folder without
  putting it in another.
- Focus a folder to see only its contents, with breadcrumbs back out.
- Collapse folders you are not working in.

**Deleting a folder does not delete its sessions.** They move up to the parent
folder, or to the workspace root if the folder was top level. There is no
variant that discards the contents, which is deliberate — a mis-click on a
folder should never lose work.

Drag and drop works the same way on web, iOS and Android, including
drag-scrolling when the target is off screen. If the server rejects a change
you made while offline, the move rolls back rather than silently diverging.

## Tags

Tags cut across folders. A session lives in exactly one folder but can carry
several tags, so tags are the right tool for a state or a theme that spans
projects — `needs-review`, `flaky`, `customer-x`.

Filter by one tag or several at once. Deleting a tag removes it from every
session that carried it and leaves the sessions alone.

## Pins

Pin the few sessions you keep coming back to and they stay at the top of the
list, above everything else, regardless of folder.

Because pins sit outside the Active and Inactive sections, a pinned row says
for itself when its session is no longer live: it shows **last seen …** under
the title. A quiet pinned row with nothing under its title is live. Anywhere in
the list, a session that is not live also has a dimmed avatar or agent logo.

Pinned sessions appear during the first paint of a long list rather than after
you scroll, which is the point of pinning them. Archiving a session removes it
from the pinned list and gives the pin quota back.

## Selecting several at once

Long-press a row, or use its menu, to start a selection. Then archive, delete,
move, mark read, or change attention handling for all of them together. The
selection survives the list updating underneath you and survives scrolling.

## Ordering

Within a scope — pinned, a folder, a tag, a workspace, a group — you can set
your own order rather than accepting the default sort. That order is stored per
scope, so the arrangement inside one folder does not disturb another.

## Limits

Generous, but not unbounded. Each is per account:

| Thing | Limit |
| --- | --- |
| Folders | 500 |
| Tags | 500 |
| Pinned sessions | 1000 |
| Session attention choices and reminders | 500 |
| Workspace and group labels | 1000 |
| Sessions changed in one bulk action | 500 |
| Custom order entries per scope | 1000 |

These bound the snapshot every client parses on first paint, which is why they
exist at all. A write past the limit is refused with an explanation rather than
being accepted and silently dropped.
